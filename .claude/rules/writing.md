# Writing

Applies to every prose file: rules, docs, OpenSpec artifacts, pull request bodies.

## Simple and clear

- Write the way you would explain it to a colleague at the desk. No academic tone, no clever phrasing.
- One idea per sentence. Short words over long ones.
- Say the thing directly. No hedging, no preamble, no summary at the end.
- No long paragraphs. Bullets over prose; a paragraph is at most three sentences.
- A reader who knows the repo understands it on the first read.

## Shape

- Short headings, one-line bullets, one fact per bullet.
- A bullet is one sentence with a verb, about 20 words.
- A table only for data that is tabular.
- No em-dashes, no parentheticals, no arrows.

## Content

- Name a file, function or flag only when the reader has to go there.
- Name a standard pattern by its common name, like Arrange-Act-Assert, instead of describing its shape.
- State a decision once; the reason lives in one place, not beside every mention.
- Short is a form, not a cut. What the agent executes keeps every path, value and command it needs.
